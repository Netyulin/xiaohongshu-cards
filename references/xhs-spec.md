# 小红书卡片改写稿速查（content.json）

写 `content.json` 用。只描述内容和结构，不含颜色字体——同一份稿子换主题不用重写。

> 字数一律按**视觉宽度**算：一个汉字或全角标点 = 1，英文字母/数字/半角符号 = 0.5。
> 文本里只能用 `**加粗**`（每段最多 1–2 处）和 `\n`（只在 title / heading 里用来断行），其它 Markdown 会被原样转义。

## 1. 骨架

```jsonc
{
  "lang": "zh",
  "theme": "editorial",                 // 主题名；用户没指定就按第 7 节选
  "title": "2027 最赚钱的\nAI 生意",       // 每张卡的页眉名，建议 2 行、每行 ≤ 12 字
  "series": "每周拆一篇好文章",           // 可选，页眉左侧栏目名
  "source": { "author": "…", "title": "…", "platform": "X 文章", "date": "2026-11-03", "url": "…" },
  "footnote": "…",                       // 可选，页脚小字
  "pages": [
    {
      "part": "第一部分 · 技能与市场",     // 副标题
      "intro": "2–3 句导语，说明这组图讲什么",   // ≤ 120 字
      "sections": [ Section, … ],
      "closing": "收束句 + 预告"            // ≤ 60 字
    }
  ]
}
```

**Section（普通节）**

```jsonc
{
  "label": "技能",                       // 显示成 "01 / 技能"，编号自动连续
  "heading": "注意力\n决定一切",          // ≤ 16 字
  "paragraphs": ["…", "…"],             // 1–3 段，每段 60–90 字，合计 ≥ 100 字
  "bullets": ["…"],                     // 0–3 条，每条 ≤ 30 字
  "takeaway": "一句收束金句",             // ≤ 26 字
  "figures": [ Figure, Figure ],         // 0–2 张，推荐 2 张
  "panel": { "type": "table|cards|quote", "title": "… · 他的看法", … },
  "card": { … }                          // 卡片专用，见下
}
```

**Figure**：`{"type": "bar|flow|compare|…", "caption": "≤ 24 字，说清这张图想让读者看到什么", "note": "≤ 20 字，来源/单位"}`。
图表类型见上游 `article-rewrite/references/figures.md`（bar 柱状、flow 流程、compare 对比等 20 多种）。

**Panel**（图下的彩色底板）：`type` 三选一
- `table`：`rows: [[短标签, 解释], …]`，2–5 行，标签 ≤ 10 字、解释 ≤ 50 字
- `cards`：`items: [{title, text}, …]`，2–9 张
- `quote`：`text` ≤ 160 字 + 可选 `note`

面板标题写成 `<这是什么> · <出处>`（"他的数字 · 编者核对"），让读者分清原文和编者加工。

**Section（checklist，行动清单）** —— 注意它会占多张卡：

```jsonc
{
  "kind": "checklist",
  "label": "执行",
  "heading": "创始人执行清单",
  "stages": [ { "label": "第 1 阶段", "title": "定下打法", "items": ["…"], "done": "做完的标准" }, … ],  // 2–6 个阶段
  "guard": { "title": "该避开什么", "items": ["…"] },        // 可选
  "note": "阶段划分与顺序出自编者"                            // 可选
}
```

## 2. 张数数学（定张数就看这一节）

```
卡片总数 = 1（封面） + Σ每节贡献 + 1（末张「全文要点」）
```

| 每节 | 贡献张数 |
|---|---|
| 普通节（`mode` 缺省或 `single`） | 1 |
| `"card": {"mode": "split"}` | 2 |
| `"card": {"mode": "skip"}` | 0 |
| `kind: "checklist"` | 按阶段数自动分张（1–6 张） |

所以 **目标 N 张 → 正文卡需要 N-2 张**。

例：目标 8 张 = 封面 1 + 正文 5 + 末张 1 → 写 5 个普通节（或 4 个普通节 + 1 个 `split` 节）。

用 `count.mjs --target N` 核对，别手算。

## 3. 卡片字段 `card`

```jsonc
"card": {
  "mode": "single",          // single（默认）| split（拆两张）| skip（不出现）
  "text": "…",               // 卡片正文 ≤ 90 字；缺省用 paragraphs[0]
  "bullets": ["…"],          // 可选 ≤ 3 条，每条 ≤ 26 字
  "figure": 0,               // 用哪张图：0（默认）/ 1 / "none"
  "panel": false,            // single 模式下要不要带数据面板
  "style": "quote",          // 可选，整页卡型：quote | number | image
  "quote": "…",              // quote 卡的句子 ≤ 26 字，缺省用 takeaway
  "number": { "value": "73%", "unit": "", "label": "…" }   // number 卡
}
```

- **一张卡只讲一件事**：正文比长图短，把要点提到 `card.text`。
- **一张卡只放一张图**（默认第 1 张或原文配图）。要上第 2 张图/面板 → `"mode": "split"`。
- **整页卡型给节奏**：每 3–4 张内容卡安排一张 `quote` / `number` / `image`。整页卡**替换**该节内容（图和面板不上卡）；这节内容也要保留就写 `"mode": "split", "style": "quote"`。
- **大数字要回答本节标题**：标题说"每周发 3 条"，大数字就该是 3。
- 这节对小红书读者不重要 → `"mode": "skip"`（调张数时最常用的一招）。

## 4. 封面 `cover`

封面决定点击率，比长图标题**更短、更有冲突**。不写 `style` 时：有插画用 `image`，有 `number` 用 `number`，有 `versus` 用 `versus`，其余 `hook`。

| style | 样子 | 字段 |
|---|---|---|
| `hook`（默认） | 标题最大，底部主色带放导语 + 最多 4 条要点 | `title`、`subtitle`、`points` |
| `number` | 巨大数字 + 一句解释 | `number: {value ≤ 5 字符, unit, label}` |
| `versus` | 左右对比，右边是答案 | `versus: {left, right}`，各 `{label, value ≤ 4 字符, note}` |
| `quote` | 大引号 + 一句话 + 署名 | `title` 写那句话，`by` 署名 |
| `image` | 插画通栏，标题在下 | `illustration` |
| `toc` | 标题 + 目录 | 可选 `points` |

```jsonc
"cover": {
  "style": "hook",
  "title": "一个人\n就是一支\n**创意团队**",     // 2–3 行，每行 ≤ 10 字，用 ** 标 1 个关键词
  "kicker": "Dan Koe 长文拆解 · 8 张图",        // 可选
  "subtitle": "2027 年最赚钱的 AI 生意，不是做工具，而是替品牌抓住注意力。",  // ≤ 60 字
  "points": ["为什么最值钱", "团队怎么搭", "第一个客户"],   // hook 显示前 4 条、每条 ≤ 12 字
  "cta": "收藏这组图，开始搭你的内容系统"        // 可选，末张底部按钮
}
```

数字必须是原文里的。封面 `points` 建议写成"N 张图讲什么"的目录感。

## 5. 小红书文案 `xhs`

```jsonc
"xhs": {
  "title": "2027最赚钱的AI生意",        // ≤ 20 个字符（字母空格也算），保守少用空格
  "caption": "…",                      // ≤ 1000 字，建议 300–600 字
  "tags": ["AI创业", "个人品牌", "内容创作", "Claude Code", "副业"]   // 5–8 个，不用写 #
}
```

正文写法：
1. 第一句是钩子（问题或反常识判断），别用"今天给大家分享"。
2. 2–3 句说这组图解决什么、适合谁看。
3. 3–5 条要点，每条一行。
4. 注明原作者："内容整理自 Dan Koe 的 X 长文《…》"（小红书正文外链不可点，写清作者和标题）。
5. 最后一句引导互动或提醒收藏。

标签选法：1–2 个大类 + 2–3 个具体主题 + 1–2 个人群/场景。

## 6. 发布备选标题 `publish.titles`

```jsonc
"publish": { "titles": { "xhs": ["≤ 20 字符", "…", "…"] } }
```

3 个角度不同（给结果 / 给数字 / 点反常识），不给用户挑的时候用不上，但缺了会出提示。

## 8. 硬限制速查

| 项 | 限制 |
|---|---|
| 小红书单篇图数 | ≤ 18（建议 10–16） |
| 小红书标题 | ≤ 20 字符 |
| 小红书正文 | ≤ 1000 字 |
| 卡片正文 `card.text` | ≤ 90 字 |
| `card.bullets` | ≤ 3 条，每条 ≤ 26 字 |
| 封面 `points` | hook ≤ 4 条 / 每条 ≤ 12 字；toc 3–6 条 / 每条 ≤ 16 字 |
| `takeaway` / `card.quote` | ≤ 26 字 |
| 别人文章的人称 | 不得用"我"，封面、标题、备选标题全部第三人称 |

## 9. 校验提示怎么修

| 提示 | 怎么改 |
|---|---|
| 数字在原文里找不到 | 换成原文数字，或在 note 里注明"未核对" |
| 第一人称 | 改成第三人称（"一家社区面包店" 而不是 "我的面包店"） |
| 卡片正文只有约 50 字 | 写到 60–90 字，讲清怎么做 |
| 封面要点偏长 | 压到 ≤ 12 字 |
| 没有备选标题 | 补 `publish.titles.xhs` 3 条 |
| 整页卡偏少 | 每 3–4 张内容卡安排一张 `quote`/`number`/`image` |
| 原文配图一张没用 | 在某节的 `card.figure` 里指定 |

**只调张数、不删内容**：加节/拆节（+1）、`split`（+1）、`skip`（-1）、合并两节（-1）。
